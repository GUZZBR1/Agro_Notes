# Google Drive export setup

Google Drive is an export destination only. Google Sheets remains the Agro Notes source of truth, and exports are generated by the existing XLSX builder. The user connection only grants access to files created by Agro Notes.

## Google Cloud setup

1. Select or create the Google Cloud project used by Agro Notes.
2. Enable the Google Drive API.
3. Configure Google Auth Platform branding and audience. For an external app in **Testing**, add each tester under **Audience → Test users**.
4. Under **Data Access**, declare `https://www.googleapis.com/auth/drive.file`. The server requests this same scope; it does not request `drive` or `drive.readonly`.
5. Under **Clients**, create an OAuth client with application type **Web application**.
6. Add the exact public callback URL `https://YOUR_PUBLIC_HOST/oauth/google/callback` to **Authorized redirect URIs**. The callback must be reachable over HTTPS in the deployed environment.
7. Copy the client ID and client secret into the server's secret manager or private `.env` file.

Google's guides: [enable Drive API and create a web OAuth client](https://developers.google.com/workspace/drive/api/quickstart/js), [configure OAuth consent and test users](https://developers.google.com/workspace/guides/configure-oauth-consent), and [select Drive scopes](https://developers.google.com/workspace/drive/api/guides/api-specific-auth).

## Environment

Set these values in the deployment environment. Do not commit `.env` or the encryption key.

```env
GOOGLE_OAUTH_CLIENT_ID=
GOOGLE_OAUTH_CLIENT_SECRET=
GOOGLE_OAUTH_REDIRECT_URI=https://YOUR_PUBLIC_HOST/oauth/google/callback
GOOGLE_DRIVE_SCOPE=https://www.googleapis.com/auth/drive.file
GOOGLE_OAUTH_TOKEN_ENCRYPTION_KEY=
```

Generate a Fernet key once and store it in a secret manager:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Keep the encryption key separate from the Google Sheets data. Losing it requires users to disconnect and reconnect. Rotating it requires a planned re-encryption of all active stored tokens.

The Google service account still needs editor access to the Agro Notes spreadsheet. It does not access users' Drive files.

## User flow and limitations

- An already-authorized user sends `/conectar_drive` or asks to connect their Google Drive in a private chat. Agro Notes sends a short-lived link; after Google consent, the user must confirm the pending connection in the same Telegram account. This final confirmation prevents a forwarded link from silently routing farm exports to another person's Drive.
- `/desconectar_drive` marks the connection unusable and asks Google to revoke the refresh token. If Google's revocation endpoint is unreachable, the local connection is still disabled; the user can also remove Agro Notes under their Google Account's third-party access settings.
- “Salva minha planilha no Drive” creates the existing property-scoped XLSX in memory and saves it under `Agro Notes/Exportações`. Repeating an export with the same filename updates the app-created file rather than creating another copy. Files are not made public.
- The connection is bound to the Telegram user and the property already authorized for that account. User text and callback parameters cannot choose another user, property, or connection.
- OAuth state and PKCE verifier are short-lived, one-use, and persisted as hashes/encrypted values in separate Sheets tabs. Refresh tokens are encrypted before persistence; access tokens are held only in memory during each Drive operation.
- Without OAuth credentials and an encryption key, the application still starts and the rest of the bot works; Drive connection and export report that setup is unavailable. Unit tests use mocks. A real consent/upload test remains `WAITING_FOR_GOOGLE_OAUTH_CREDENTIALS` until valid credentials and a test account are configured.
- In Google's External **Testing** mode, Drive refresh tokens expire after seven days. Move the consent configuration to production and complete any required verification before relying on durable user connections. See [Google OAuth token behavior](https://developers.google.com/identity/protocols/oauth2/).

## Callback logging

OAuth callback query parameters contain a short-lived authorization code and state. Run Uvicorn with access logging disabled and configure any reverse proxy or platform logs to omit the query string for `/oauth/google/callback`:

```bash
uvicorn agro_notes.main:app --host 0.0.0.0 --port 8000 --workers 1 --no-access-log
```

Do not paste callback URLs into support tickets or logs.

## Invitation revocation

Run `python -m agro_notes.access_admin revoke-code <ID>` on the same host and filesystem as the bot, with the bot stopped. The bot holds a local SQLite process lock while running; the CLI refuses to revoke a code while that lock is held. If the bot runs on another machine, stop it there before running the administrative command.
